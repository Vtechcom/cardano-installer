# Cardano Installer (Hydra / Cardano Node Setup)

A small utility (written in Rust) to help initialize and run a Cardano node using Docker and a Mithril snapshot builder.

This project is an interactive CLI that:

- Detects presence of Docker and prompts to install it (Linux script stub).
- Searches for an existing `cardano-node` container and prints its status.
- Generates a `docker-compose.yml` for a selected network (mainnet/preprod/sanchonet/custom).
- Downloads a Mithril client (platform-aware selection based on OS/ARCH) and shows a progress bar for the download.
- Runs Mithril snapshot logic (stubbed) to prepare/restore Cardano DB snapshots.
- Starts `docker compose up` with the generated compose file.

Note: Some flows are currently *stubs* or *demo* (e.g., Docker install automation, actual mithril-client run) and flagged with TODOs in the source.

## Quick Start

### Prerequisites

- Rust toolchain (cargo)
- Docker (if not already installed, the CLI may prompt to install on Linux)

### Build and run

cargo run -- --verbose
```powershell
# Build
cargo build

# Run (interactive)
cargo run -- --verbose

# Alternative: install the binary locally
cargo install --path .
# then run
cardano-installer --help
```

### CLI Usage

The utility uses `clap` and currently accepts a `--verbose` flag to print extra information:

```text
cardano-installer [OPTIONS]

Options:
  -v, --verbose    Enable verbose output
```

When running, the tool will:

1. Detect Docker and show Docker version if available.
2. Check for an existing `cardano-node` container and report its status.
3. If not present, ask to run setup flow (Docker + Mithril snapshot) and will:
   - Prompt to choose the network (mainnet/preprod/sanchonet/custom).
   - Generate a `docker-compose.yml` file in the project directory for the selected network.
   - Detect Mithril binary for your platform (Linux/Windows/macOS + arch), download into `./.download/`, and run a progress bar.
   - Run Mithril snapshot logic (currently a TODO/stub) to restore the DB folder.
   - Bring up Docker with `docker compose up -d`.

## Project Layout

- `src/main.rs` — main CLI and flow orchestration.
- `src/configs/` — configuration helpers and utilities
  - `mithril.rs` — mithril config parsing and platform mapping
  - `mithril.yaml` — embedded default YAML used by `mithril.rs`
  - `download_file.rs` — helper to download a file to `./.download/` using blocking `reqwest` and `indicatif` for a progress bar
- `docker-compose.yml` — generated by the CLI (sample content created based on selected network and mounts)

## Where things are stubbed or TODO

- `install_docker`: The flow currently demonstrates the intent to use `curl https://get.docker.com | sh` for Linux; you'll want to handle OS-specific installers and require correct elevated permissions.
- `download_mithril_client`: Currently a demonstration of the progress bar; it calls `download_file` but there is no extraction+binary install logic or permission fixups. On non-Windows platforms you will want to set the executable bit and extract the tarball.
- `run_mithril_snapshot`: Stubbed. Intended to run commands like:

```
mithril-client cardano-db download --network <network> --dest ./db/<network>
```

- `download_network_config_stub`: Networking / topology / configuration download is a placeholder.

## Development notes

- The project uses `anyhow` for convenient error handling and `clap` for command-line parsing.
- The default mithril config file is embedded via `include_str!("mithril.yaml")`. If you prefer a runtime-configurable approach, load YAML from `dirs::config_dir()` and write the default on the first run.
- `download_file` saves files to `./.download/`. This directory is created automatically.
